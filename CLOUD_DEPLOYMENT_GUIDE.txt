================================================================================
                          SECTION 2: CLOUD PROVIDER SETUP
================================================================================

-------------------------
2.1 AWS EC2 SETUP
-------------------------

1. Launch EC2 Instance:
   - Instance Type: t3.medium (2 vCPU, 4GB RAM) minimum
   - OS: Ubuntu 22.04 LTS
   - Storage: 50GB gp3

2. Security Group Configuration:
   Inbound Rules:
   ┌─────────────────┬────────────────┬────────────────┐
   │ Type            │ Port           │ Source         │
   ├─────────────────┼────────────────┼────────────────┤
   │ HTTP            │ 80            │ 0.0.0.0/0      │
   │ HTTPS           │ 443           │ 0.0.0.0/0      │
   │ SSH             │ 22            │ YOUR_IP/32     │
   └─────────────────┴────────────────┴────────────────┘

3. Install Docker:
   sudo apt update
   sudo apt install -y docker.io docker-compose
   sudo usermod -aG docker ubuntu

-------------------------
2.2 GCP COMPUTE ENGINE
-------------------------

1. Create VM Instance:
   - Machine Type: e2-medium (2 vCPU, 4GB)
   - Boot Disk: Ubuntu 22.04 LTS
   - Firewall: Allow HTTP/HTTPS

2. Set up Firewall Rules:
   gcloud compute firewall-rules create allow-http --allow tcp:80
   gcloud compute firewall-rules create allow-https --allow tcp:443

-------------------------
2.3 DOMAIN & DNS SETUP
-------------------------

Required DNS Records:
┌──────────────┬───────────────┬─────────────────────────────────┐
│ Record Type  │ Name          │ Value                           │
├──────────────┼───────────────┼─────────────────────────────────┤
│ A            │ qa-hub        │ YOUR_VM_PUBLIC_IP               │
│ A            │ jenkins       │ YOUR_VM_PUBLIC_IP               │
│ CNAME        │ www           │ qa-hub.yourdomain.com           │
└──────────────┴───────────────┴─────────────────────────────────┘

                          SECTION 3: CLOUD-DEPLOYMENT FILES

Create docker-compose.cloud.yml:

version: '3.8'

services:
  nextjs:
    build:
      context: ./frontend
    container_name: qahub-nextjs
    restart: unless-stopped
    ports:
      - "3000:3000"
    environment:
      - NODE_ENV=production
      - NEXT_PUBLIC_API_URL=https://qa-hub.yourdomain.com
      - JENKINS_URL=http://jenkins:8080/jenkins
      - JENKINS_USER=${JENKINS_USER}
      - JENKINS_PASS=${JENKINS_PASS}
      - AUTOMATION_DIR=/data/automation
      - TARGET_APP_URL=https://hris-staging.kantorku.id/
    volumes:
      - automation_scripts:/data/automation
      - reports_data:/data/reports
    depends_on:
      - jenkins
    networks:
      - qa-hub-network
    deploy:
      replicas: 1
      resources:
        limits:
          cpus: '1'
          memory: 1G

  jenkins:
    build:
      context: ./jenkins
    container_name: qahub-jenkins
    restart: unless-stopped
    ports:
      - "8080:8080"
    volumes:
      - jenkins_home:/var/jenkins_home
      - reports_data:/data/reports
      - automation_scripts:/data/automation
      - /var/run/docker.sock:/var/run/docker.sock
    group_add:
      - "0"
    environment:
      - JENKINS_OPTS=--prefix=/jenkins
      - JENKINS_ADMIN_USERNAME=${JENKINS_USER}
      - JENKINS_ADMIN_PASSWORD=${JENKINS_PASS}
      - DOCKER_HOST=unix:///var/run/docker.sock
    networks:
      - qa-hub-network

  playwright-runner:
    build:
      context: ./playwright-runner
    volumes:
      - automation_scripts:/data/automation
      - reports_data:/data/reports
    networks:
      - qa-hub-network
    deploy:
      resources:
        limits:
          cpus: '2'
          memory: 2G
    restart: on-failure

volumes:
  jenkins_home:
    driver: local
  automation_scripts:
    driver: local
  reports_data:
    driver: local

networks:
  qa-hub-network:
    driver: bridge

4.1 Cloudflare (Recommended - Free SSL)

1. Add your domain to Cloudflare

4.3 Nginx Reverse Proxy Configuration

upstream nextjs {
    server 127.0.0.1:3000;
}

upstream jenkins {
    server 127.0.0.1:8080;
}

server {
    listen 80;
    server_name qa-hub.yourdomain.com;

    location / {
        proxy_pass http://nextjs;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection 'upgrade';
        proxy_set_header Host $host;
        proxy_cache_bypass $http_upgrade;
    }
}

server {
    listen 80;
    server_name jenkins.yourdomain.com;

    location / {
        proxy_pass http://jenkins;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Jenkins specific headers
        proxy_set_header X-Jenkins Sprint-Token "";
        proxy_buffering off;
        proxy_request_buffering off;
        proxy_read_timeout 300s;
        proxy_connect_timeout 60s;
    }
}

STEP 1: Prepare Cloud VM
-------------------------
ssh -i your-key.pem ubuntu@your-vm-ip

-------------------------
git clone https://your-repo/qa-automation-hub.git
cd qa-automation-hub

git clone https://github.com/your-org/qa-automation-scripts.git /data/automation

-----------------------------
cp .env.example .env.production
nano .env.production  # Update all values

--------------------------------------
Edit frontend/src/app/api/run/route.ts:
const JENKINS_URL = process.env.JENKINS_URL || "http://jenkins:8080/jenkins";

------------------------------
docker-compose -f docker-compose.cloud.yml up -d --build

STEP 6: Verify Services
-----------------------
docker-compose -f docker-compose.cloud.yml ps
curl -f http://localhost:3000
curl -f http://localhost:8080/jenkins

STEP 7: Configure DNS
--------------------
Add A records at your DNS provider:
qa-hub.yourdomain.com -> VM_IP
jenkins.yourdomain.com -> VM_IP

STEP 8: Setup SSL (if using Nginx)
----------------------------------
sudo apt install nginx certbot python3-certbot-nginx
sudo certbot --nginx -d qa-hub.yourdomain.com -d jenkins.yourdomain.com

STEP 9: Update Scripts (Production)
------------------------------------
# For Git-based workflow (recommended):

12.1 Automated Backup Script (backup.sh)
-----------------------------------------
#!/bin/bash
DATE=$(date +%Y%m%d_%H%M%S)
BACKUP_DIR=/opt/backups

# Backup Jenkins Home
tar -czf $BACKUP_DIR/jenkins_home_$DATE.tar.gz /var/jenkins_home

# Backup Reports
tar -czf $BACKUP_DIR/reports_$DATE.tar.gz /data/reports

# Upload to S3
aws s3 cp $BACKUP_DIR/jenkins_home_$DATE.tar.gz s3://qa-hub-backups/
aws s3 cp $BACKUP_DIR/reports_$DATE.tar.gz s3://qa-hub-backups/

# Keep only last 30 days
find $BACKUP_DIR -mtime +30 -delete

12.2 Restore Procedure
-----------------------
# Stop services
docker-compose -f docker-compose.cloud.yml down

# Restore Jenkins
tar -xzf /opt/backups/jenkins_home_20240101_120000.tar.gz -C /

# Start services
docker-compose -f docker-compose.cloud.yml up -d

13.2 NAMED VOLUME (Current Setup - Production Ready)
-----------------------------------------------------

Current Configuration:
- docker-compose uses: automation_scripts:/data/automation
- Scripts stored in Docker volume (persistent)
- Updates via: Web UI Upload OR manual sync

How to Update Scripts (Production):

OPTION A: Web UI Upload (Simplest)
-----------------------------------
1. Go to QA Hub website: https://qa-hub.yourdomain.com/scripts
2. Click "Upload Script" button
3. Select .spec.ts file
4. File is added to Docker volume

⚠️  Note: This creates a COPY in the volume. Local files are NOT synced.

OPTION B: Volume Mount with Initial Sync (Recommended for Cloud)
----------------------------------------------------------------
1. On Cloud VM, create a folder:
   sudo mkdir -p /opt/qa-automation/scripts

2. Copy initial scripts from local to VM:
   rsync -avz ./Automation-Kantorku ubuntu@your-vm:/opt/qa-automation/scripts/

3. Update docker-compose.cloud.yml:
   volumes:
     - /opt/qa-automation/scripts:/data/automation

4. To update later:
   rsync -avz ./Automation-Kantorku ubuntu@your-vm:/opt/qa-automation/scripts/

13.6 TROUBLESHOOTING SCRIPT SYNC ISSUES
----------------------------------------

PROBLEM: Scripts not updating in production
SOLUTION:
1. Check if volume is correctly mounted: docker exec <container> ls /data/automation
2. For Git: Verify git remote and branch: cd /data/automation && git status
3. For S3: Check AWS credentials and bucket permissions
4. For Web Upload: Verify file was uploaded (check file listing in UI)

PROBLEM: Duplicate scripts appearing in listing
SOLUTION:
1. Web upload creates copies - don't upload the same file twice
2. Delete duplicates: docker exec <container> rm /data/automation/tests/duplicate.spec.ts
3. Use Git workflow to avoid duplicates

PROBLEM: "Script not found" error when running
SOLUTION:
1. Verify SCRIPT_PATH parameter is correct (e.g., "learning-course/course-crud.spec.ts")
2. Check file exists: docker exec <container> test -f /data/automation/tests/${SCRIPT_PATH}
3. Ensure no typos in path (case-sensitive on Linux)

================================================================================
                          SECTION 14: TROUBLESHOOTING
================================================================================

COMMON ISSUES & SOLUTIONS:

1. Jenkins Build Not Triggering
   - Check crumb authentication: GET /jenkins/crumbIssuer/api/json
   - Verify JSESSIONID cookie is sent
   - Check Jenkins logs: docker logs qahub-jenkins

2. Next.js Can't Reach Jenkins
   - Verify both in same Docker network
   - Check JENKINS_URL environment variable
   - Test network: docker exec qahub-nextjs ping jenkins

3. Report Page Blank
   - Check iframe sandbox settings
   - Verify clipboard polyfill is injected
   - Check browser console for errors

4. Playwright Tests Failing
   - Check SCRIPT_PATH exists in volume
   - Verify BROWSER environment variable
   - Check BASE_URL is accessible from runner

5. SSL Certificate Issues
   - Verify DNS is pointing to correct IP
   - Check Cloudflare SSL mode (Full strict)
   - Renew certbot: sudo certbot renew
